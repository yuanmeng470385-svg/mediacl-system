# 数字员工办公室 · 3D 动态版（v4，Three.js）设计

日期：2026-08-10
状态：设计已获用户确认（含左侧团队出勤面板），待实施

## 背景与目标

v3 俯视蓝图版（静态白色小人 + 灯带）被老板否决为"不够活"。新要求：

> 人物要 3D 的，并且是动态的；每个工位都要有桌子，桌子上有电脑；工作中的小人坐在桌前，没工作的四处走动；头上要有名字和状态。左侧加一块独立数据面板，显示团队出勤数据。

用户逐项确认的关键决策：
- **实现方式**：引入 Three.js（打破"零依赖"约定，用户拍板）——真 3D 场景 + 程序化人形 + rAF 模拟循环
- **走动范围**：空闲小人在工位排间的**过道巡逻**（不撞桌子，走到底转头）
- **状态切换**：**走位过渡**——空闲→工作：走到自己工位坐下；工作→空闲：起身离开去巡逻
- **出勤面板**：左侧独立 DOM 面板（antd），显示团队出勤数据，与 3D 场景双向联动

## 范围

**做：**
- `web/` 引入 `three` + `@types/three`（npm，Vite 直接打包）
- 3D 办公室场景：俯视相机 + 蓝图风地板（网格纹理）+ 排间发光过道 + 每工位一桌一电脑
- 程序化白色人形（无模型资产）：站立/走路/坐姿 + 四肢摆动 + 平滑姿态过渡 + 转向插值
- 模拟循环（rAF）：空闲过道巡逻、工作走向工位坐下、offline 灰化静止；数据由现有 3s 轮询驱动
- 头顶名牌（CSS2D DOM 标签）：名字 + 状态色点 + 状态文字 + 今日 N；working 附加气泡（问题片段）
- 交互：raycast 点击 = 数据抽屉；选中浮出操作卡（数据/编辑/停用·启用）；编辑仍先 detail() 防覆盖
- **左侧团队出勤面板**：出勤率环形进度 + 状态分布 + 今日对话统计 + 在岗明细列表；与 3D 场景双向联动（点击行聚焦工位，选中小人高亮行）
- 工具条 / 切表 / 新增 / 轮询降级 / 编辑 detail 防覆盖 / 状态条：全部保留

**不做：**
- 零后端改动；live-status 接口不动（出勤面板数据全部从现有响应推导）
- 移动端 RN 不改；`LiveStatusStrip.tsx` 不改代码
- 不做真实模型资产/骨骼动画（程序化人形 + 过程动画）
- 不做小人互相碰撞（巡逻路径避开桌子即可，小人可交错穿过）
- 不做音效、不做多人镜头跟随、不做拖拽移动工位

## 架构

```
live-status 轮询（3s，现有接口与页面逻辑不动）
  → SpecialistOffice（工具条 + 左侧出勤面板 + 右侧 3D 场景）
      ├─ AttendancePanel（DOM/antd，从 items 推导出勤数据）
      │    ↕ 双向联动（selectedId 双向同步）
      └─ OfficeScene3D（useEffect 挂载 Three.js：
            场景/相机/灯光 + 程序化人物 + rAF 模拟循环 + CSS2D 名牌）
             └─ 状态机：每专员 current {state, pose, pos, heading, target}
  → 回调（onViewData/onEdit/onToggleStatus）与 v3 完全一致
```

## 组件设计

### 1. 依赖与渲染

- `npm i three @types/three`（web/ 目录）；Vite 原生支持
- `WebGLRenderer({ antialias: true })` + `PerspectiveCamera`：俯视 3D 机位（fov ≈ 45，机位高角度俯瞰办公室，保持 v3"俯视蓝图"观感；具体坐标实现时定）
- `CSS2DRenderer`（three/examples/jsm/renderers/CSS2DRenderer，同包内置）渲染头顶名牌——DOM 标签跟随人物
- 页面离开时清理：cancelAnimationFrame + renderer.dispose() + geometry/material dispose

### 2. 3D 场景与视觉（保留蓝图语言）

- **地板**：PlaneGeometry + CanvasTexture 程序生成网格纹理（深蓝灰 `#101828→#1d2a3d` + 浅蓝 `#58a6ff` 网格线，26px 单元比例映射）
- **过道**：排间发光线条（emissive 细条，`#58a6ff`），划分过道与办公区域
- **工位（每专员一个）**：桌子 = 深色桌面 box + 桌腿；**桌上电脑** = 显示器 box（屏幕朝前）+ 底座；桌沿浅蓝发光描边（emissive）
- **状态语义**（沿用灯带逻辑）：working 屏幕亮蓝光**脉动**（emissiveIntensity 0.6↔1）/ idle 屏幕暗 / offline 整桌灰暗（材质降亮度）
- **布局**：每排 6 桌（与 v3 一致），行数随专员数自适应，排间过道留宽；工位顺序按 live-status items 顺序（id 升序）

### 3. 人物（程序化白色人形）

- 低多边形组装（无外部资产）：白球头 + 白圆角躯干 + 双臂双腿（box），深灰 `#666` 材质强调描边感
- **三姿态 + 过程动画**：
  - **站立/走路**：双腿交替摆动（相位 sin）+ 双臂反向摆 + 身体轻微起伏；**转向平滑插值**（heading lerp）
  - **坐着**：腿收折坐姿、双手放桌面键盘、轻微打字动作（小幅度往复）
  - **offline**：灰化半透明（材质降透明度 + 灰度色）+ 静止
- **姿态过渡**：站立↔坐姿 ~0.4s 插值（腿/躯干/手姿态参数 lerp），不跳变

### 4. 模拟逻辑（"活"的核心）

- 每个专员一个模拟状态机：`{ state, pose, pos, heading, walkPhase }`
- **idle 巡逻**：在所在过道巡逻——随机选过道内的目标点 → 走过去（速度 ~0.8 单位/s）→ 到达换下一个目标点；路径仅限过道带，不进入办公区域
- **working 走位过渡**：走到自己工位桌前（沿过道接近）→ 坐下 → 屏幕亮蓝脉动；转 idle：起身 → 走入过道巡逻
- **offline**：若正在走动/工作 → 平滑停下 → 灰化；不再移动
- **数据驱动**：3s 轮询的 items 是状态源；模拟层平滑跟随（状态切换后按目标姿态/位置过渡），轮询失败保留上次模拟状态
- rAF 每帧更新所有小人 + 渲染；帧率不做人为限流（低多边形规模无压力）

### 5. 交互

- **点击**（raycast 命中人物/工位）→ `onViewData(item)`（数据抽屉，页面层不变）
- **选中** → 人物头顶名牌旁浮出操作卡：数据 / 编辑 / 停用·启用（编辑仍走页面层 detail() 先拉全量防 persona 覆盖）；点击空白取消选中
- **头顶名牌**（CSS2D，全部人物）：名字 + 状态色点（`#1677ff/#faad14/#bfbfbf`）+ 状态文字（working 显示 phase_text / idle 空闲中 / offline 离线）+ 今日 N 次；working 附加气泡「正在回答：{snippet}…」
- **hover**：光标悬停人物高亮描边（选中反馈）
- 工具条（汇总 Tag / 3s 刷新 Switch / 刷新 / 新增 / Segmented 切表）：原样保留

### 6. 团队出勤面板（左侧，DOM/antd）

位置：工具条下方，页面左侧固定宽 **~280px**；右侧 3D 场景 flex:1。数据全部从 live-status `items/summary` 推导：

- **出勤率**：大数字百分比 + 环形进度（antd Progress dashboard）——出勤 = working + idle，离岗 = offline；`(working + idle) / 总数`（总数 0 显示 0%）
- **状态分布**：工作中 N / 空闲 N / 离线 N（状态色点，与 3D 灯带同色语义）
- **今日对话**：团队总和 + 人均（1 位小数）
- **在岗明细列表**（滚动区）：每专员一行——白色迷你头像（MiniCharacter，v3 组件复用）+ 名字 + 状态文字（phase_text / 空闲中 / 离线）+ 今日 N + 最近活跃相对时间（last_active_at）
- **双向联动**：点击明细行 → 3D 场景中该专员高亮聚焦（名牌发光 + 简单相机注视）；3D 中选中人物 → 面板对应行高亮。联动以 selectedId 状态在页面层双向同步
- 空态：无专员时显示空状态 + 新增入口（既有语义）
- 轮询失败：面板沿用上次数据（与场景一致静默降级）

### 7. 页面改造 `SpecialistOffice.tsx`

- 布局：工具条 → `<Flex>` 左侧 AttendancePanel（280px）+ 右侧 OfficeScene3D
- selectedId 状态在页面层，面板与 3D 场景双向绑定
- 其余（轮询 / toSpecialist / 编辑 detail 包装 / 降级）原样保留

## 错误处理与降级

- **WebGL 不可用**：renderer 创建失败 → antd Alert 提示"3D 场景不可用"，页面其余功能（表格视图/面板/工具条）正常
- 轮询失败：场景与面板保留上次数据（既有静默降级）
- 接口不可达首载：沿用空态语义
